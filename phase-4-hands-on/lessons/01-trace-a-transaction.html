Trace a Full Transaction

Start from a CPU cache miss and walk the whole path to data return. Doing this once makes "row hit / miss / conflict" permanent knowledge.

The three cases

Do the exercise

On paper, pick an address and walk it through for each of the three cases. Annotate every command with its governing timing:

  • Hit: RD → (CL) → data.
  • Miss: ACT → (tRCD) → RD → (CL) → data.
  • Conflict: PRE → (tRP) → ACT → (tRCD) → RD → (CL) → data.
Why this is the core exercise Nearly all DRAM performance reasoning reduces to how often you get hits vs conflicts. Lock in this trace and the simulator experiments (Lesson 4) will make immediate sense.
Check yourself
  1. Write the command+timing sequence for each of hit, miss, and conflict.
  2. Which is slowest, and why?
  3. What property of the access pattern pushes you toward hits?
