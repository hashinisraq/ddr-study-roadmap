Reliability: Data CRC & Command/Address Parity

Two lightweight guards that let DDR4 detect corruption on its buses before it turns into silent bad data.

Write data CRC

When the controller writes data, it can send a CRC checksum alongside the data burst. The chip recomputes the checksum and, if it doesn't match, flags an error - so a glitch on the data bus is detected rather than silently stored.

Command/Address (CA) parity

A garbled command is dangerous - imagine a flipped bit turning a READ into a PRECHARGE. CA parity adds a parity bit over the command/address bus so the chip can catch a corrupted command and raise an error instead of executing it.

Detect vs correct These are detection mechanisms - they catch errors so the system can retry or flag them. Full correction of stored data is ECC (an extra chip per rank, 72 bits instead of 64), standard in servers. DDR5 adds on-die ECC inside every chip (Phase 2).
