The Core Timings - and the Reason for Each

Don't memorize numbers; learn what each timing protects. Every one is a physical delay the bank needs between commands.

A read, drawn on a timeline

The timings and what they protect

TimingMeaningPhysical reason
tRCDACT → RD/WRSense amps need time to latch the row into the row buffer.
tRPPRE → next ACTBit lines must reset to the midpoint before a new row opens.
tRASACT → PRE (min)The destructive read must be fully restored before closing.
tRCACT → ACT same bank (= tRAS+tRP)Full open-use-close-reopen cycle.
CLRD → first dataFixed clocks to fetch and drive data out.
tWRlast write data → PREWritten data must settle into cells before the row closes.
tWTRwrite → readInternal data path must turn around.
tRFClength of a REFRESHRefreshing rows takes real time; the chip is busy.
tREFIavg gap between REF (~7.8 µs)Paces refresh so all cells are covered within 64 ms.
tRRDACT → ACT different banksEach activation draws a current surge; space them out.
tFAWwindow allowing only 4 ACTsFour activations in quick succession is the power ceiling.
tCCD_S / _Lcol → col, short / longBack-to-back reads are faster across bank groups than within one.
The one mental model Opening and closing rows is slow (tRCD, tRP, tRAS). Reading columns off an already-open row is fast (CL + burst). Good performance = keep useful rows open and spread work across banks and bank groups.
Check yourself
  1. Why does tRAS have a minimum (tie it back to Phase 0)?
  2. What is the difference between tRFC and tREFI?
  3. Why do tRRD and tFAW exist - what are they protecting?
